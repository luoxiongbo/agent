> 本项目是一个**极简的 AI Agent 框架**，核心代码不到 80 行，能让大语言模型（LLM）具备调用外部工具的能力。

### 1.1 学习前置知识

在开始之前，理解以下核心概念：

| 概念 | 说明 |
|------|------|
| **大语言模型（LLM）** | 能回答问题、写文章，但不知道实时信息（如当前时间、天气） |
| **Function Calling** | OpenAI 等大模型支持的功能，让模型输出"调用意图"而非直接回答 |

| **Agent** | 能调用外部工具的智能代理，弥补 LLM 的局限性 |

### Step 2.1: 工具定义（`src/tools.py`）- 第1天

**任务**：定义 Agent 可以调用的工具函数

**编写代码**：

```python
from datetime import datetime

# 获取当前日期和时间
def get_current_datetime() -> str:
    """
    获取当前日期和时间。
    :return: 当前日期和时间的字符串表示。
    """
    current_datetime = datetime.now()
    formatted_datetime = current_datetime.strftime("%Y-%m-%d %H:%M:%S")
    return formatted_datetime

def add(a: float, b: float) -> str:
    """
    计算两个浮点数的和。
    :param a: 第一个浮点数。
    :param b: 第二个浮点数。
    :return: 两个浮点数的和。
    """
    return str(a + b)

def compare(a: float, b: float) -> str:
    """
    比较两个浮点数的大小。
    :param a: 第一个浮点数。
    :param b: 第二个浮点数。
    :return: 比较结果的字符串表示。
    """
    if a > b:
        return f'{a} is greater than {b}'
    elif a < b:
        return f'{b} is greater than {a}'
    else:
        return f'{a} is equal to {b}'

def count_letter_in_string(a: str, b: str) -> str:
    """
    统计字符串中某个字母的出现次数。
    :param a: 要搜索的字符串。
    :param b: 要统计的字母。
    :return: 字母在字符串中出现的次数。
    """
    string = a.lower()
    letter = b.lower()
    count = string.count(letter)
    return f"The letter '{letter}' appears {count} times in the string."
```

**工具编写规范**：
1. **必须有 docstring**：用于描述工具功能
2. **参数必须有类型注解**：如 `a: float, b: float`
3. **返回值必须是字符串**：LLM 接收文本输入
4. **参数描述要写清楚**：`:param x: 参数说明`

**验证点**：
- [ ] 每个函数都有清晰的 docstring
- [ ] 参数有类型注解
- [ ] 返回值是字符串
- [ ] 可以在 Python 解释器中直接调用测试

### Step 2.2: 工具描述生成（`src/utils.py`）- 第2天

**任务**：将 Python 函数自动转换为 LLM 能理解的 JSON Schema 格式

**核心原理**：使用 Python 的 `inspect` 模块自动分析函数签名

**编写代码**：

```python
import inspect

# Python 类型 → JSON 类型的映射表
type_map = {
    str: "string",
    int: "integer",
    float: "number",
    bool: "boolean",
    list: "array",
    dict: "object",
}

def function_to_json(func):
    """
    将函数转换为 OpenAI Tool Schema 格式
    
    示例：
    def add(a: float, b: float) -> str:
        '''计算两数之和'''
        return str(a + b)
    
    转换后：
    {
        "type": "function",
        "function": {
            "name": "add",
            "description": "计算两数之和",
            "parameters": {
                "type": "object",
                "properties": {
                    "a": {"type": "number"},
                    "b": {"type": "number"}
                },
                "required": ["a", "b"]
            }
        }
    }
    """
    # 获取函数签名
    signature = inspect.signature(func)
    
    # 解析参数
    parameters = {}
    for param in signature.parameters.values():
        param_type = type_map.get(param.annotation, "string")
        parameters[param.name] = {"type": param_type}
    
    # 判断哪些参数是必需的（没有默认值的）
    required = [
        param.name
        for param in signature.parameters.values()
        if param.default == inspect._empty  # 没有默认值
    ]
    
    return {
        "type": "function",
        "function": {
            "name": func.__name__,
            "description": func.__doc__ or "",
            "parameters": {
                "type": "object",
                "properties": parameters,
                "required": required,
            },
        },
    }


# 测试代码
if __name__ == "__main__":
    from tools import add, get_current_datetime
    
    # 测试 add 函数
    add_schema = function_to_json(add)
    print("add 函数的 Schema:")
    import json
    print(json.dumps(add_schema, indent=2, ensure_ascii=False))
    
    print("\n" + "="*50 + "\n")
    
    # 测试 get_current_datetime 函数
    datetime_schema = function_to_json(get_current_datetime)
    print("get_current_datetime 函数的 Schema:")
    print(json.dumps(datetime_schema, indent=2, ensure_ascii=False))
```

**关键点**：
- `inspect.signature(func)`：获取函数的参数信息
- `param.annotation`：获取参数的类型注解（如 `a: float` 中的 `float`）
- `param.default`：获取参数的默认值

**验证点**：
- [ ] 用 `add` 函数测试，输出正确的 JSON Schema
- [ ] 包含 name, description, parameters
- [ ] 参数类型映射正确（float → number）
- [ ] 必需参数列表正确（没有默认值的参数）

### Step 2.3: Agent 核心类（`src/core.py`）- 第3-4天

**任务**：实现 Agent 的完整逻辑

**核心理解**：Agent 需要**两次调用 LLM**：
1. **第一次调用**：告诉 LLM 有哪些工具，让它判断是否需要调用
2. **第二次调用**：将工具执行结果告诉 LLM，让它生成自然语言回复

**编写代码**：

```python
from openai import OpenAI
import json
from typing import List, Dict, Any
from src.utils import function_to_json
from src.tools import get_current_datetime, add, compare, count_letter_in_string


# 系统提示词，定义 Agent 的角色和行为
SYSTEM_PROMPT = """
你是一个叫不要葱姜蒜的人工智能助手。你的输出应该与用户的语言保持一致。
当用户的问题需要调用工具时，你可以从提供的工具列表中调用适当的工具函数。
"""


class Agent:
    def __init__(self, client: OpenAI, model: str = "Qwen/Qwen2.5-32B-Instruct", 
                 tools: List = [], verbose: bool = True):
        """
        初始化 Agent
        
        :param client: OpenAI 客户端实例
        :param model: 使用的模型名称
        :param tools: 可用的工具函数列表
        :param verbose: 是否打印调试信息
        """
        self.client = client        # OpenAI API 客户端
        self.tools = tools          # 工具函数列表
        self.model = model          # 模型名称
        self.verbose = verbose      # 调试模式
        
        # 对话历史记录（包含系统提示）
        self.messages = [
            {"role": "system", "content": SYSTEM_PROMPT},
        ]

    def get_tool_schema(self) -> List[Dict[str, Any]]:
        """
        获取所有工具的 JSON Schema 描述
        用于传递给 LLM，让它知道有哪些工具可用
        """
        return [function_to_json(tool) for tool in self.tools]

    def handle_tool_call(self, tool_call):
        """
        处理 LLM 请求的工具调用
        
        :param tool_call: LLM 返回的工具调用请求
        :return: 工具执行结果消息
        """
        # 提取工具调用信息
        function_name = tool_call.function.name      # 函数名
        function_args = tool_call.function.arguments # 参数（JSON字符串）
        function_id = tool_call.id                   # 调用ID
        
        # 执行工具函数
        # eval(f"{function_name}(**{function_args})") 会动态执行函数
        # 例如：eval("add(**{'a': 1, 'b': 2})") → add(a=1, b=2)
        function_call_content = eval(f"{function_name}(**{function_args})")
        
        # 返回结果消息（tool 类型）
        return {
            "role": "tool",
            "content": str(function_call_content),
            "tool_call_id": function_id,
        }

    def get_completion(self, prompt: str) -> str:
        """
        处理用户输入，获取回复
        
        这是 Agent 的核心逻辑，包含完整的对话流程
        """
        # 1. 将用户消息加入历史
        self.messages.append({"role": "user", "content": prompt})
        
        # 2. 第一次调用 LLM，传入工具描述
        response = self.client.chat.completions.create(
            model=self.model,
            messages=self.messages,
            tools=self.get_tool_schema(),  # 告诉 LLM 有哪些工具
            stream=False,
        )
        
        # 3. 检查 LLM 是否需要调用工具
        if response.choices[0].message.tool_calls:
            # LLM 想调用工具
            
            # 将 LLM 的回复加入历史（包含 tool_calls 信息）
            self.messages.append({
                "role": "assistant", 
                "content": response.choices[0].message.content or "",
                "tool_calls": [
                    {
                        "id": tc.id,
                        "type": tc.type,
                        "function": {
                            "name": tc.function.name,
                            "arguments": tc.function.arguments,
                        }
                    }
                    for tc in response.choices[0].message.tool_calls
                ]
            })
            
            # 处理所有工具调用请求
            tool_list = []
            for tool_call in response.choices[0].message.tool_calls:
                # 执行工具并将结果添加到消息列表中
                result = self.handle_tool_call(tool_call)
                self.messages.append(result)
                
                tool_list.append([
                    tool_call.function.name, 
                    tool_call.function.arguments
                ])
            
            # 打印调试信息
            if self.verbose:
                print("调用工具：", response.choices[0].message.content, tool_list)
            
            # 4. 第二次调用 LLM，传入工具执行结果
            response = self.client.chat.completions.create(
                model=self.model,
                messages=self.messages,
                tools=self.get_tool_schema(),
                stream=False,
            )
        
        # 5. 将最终回复加入历史
        final_content = response.choices[0].message.content
        self.messages.append({
            "role": "assistant", 
            "content": final_content
        })
        
        # 6. 返回最终回复
        return final_content
```

**核心逻辑解析**：

#### 对话流程管理

```
┌────────────────────────────────────────────────────────────┐
│                      对话历史 (messages)                     │
├────────────────────────────────────────────────────────────┤
│ 1. 系统消息 {"role": "system", "content": "你是一个..."}    │
├────────────────────────────────────────────────────────────┤
│ 2. 用户消息 {"role": "user", "content": "现在几点了？"}       │
├────────────────────────────────────────────────────────────┤
│ 3. 助手消息 {"role": "assistant", "content": "",            │
│              "tool_calls": [{...}]} ← 想调用工具            │
├────────────────────────────────────────────────────────────┤
│ 4. 工具消息 {"role": "tool", "content": "2024-01-01...",   │
│              "tool_call_id": "call_xxx"}                   │
├────────────────────────────────────────────────────────────┤
│ 5. 最终回复 {"role": "assistant", "content": "现在是..."}    │
└────────────────────────────────────────────────────────────┘
```

#### 两次调用 LLM 的原因

1. **第一次调用**：告诉 LLM 有哪些工具，让它判断是否需要调用
2. **第二次调用**：将工具执行结果告诉 LLM，让它生成自然语言回复

```
第一次调用：
用户: "现在几点？"
LLM: 我需要调用 get_current_datetime()
     ↓
程序执行工具
     ↓
第二次调用：
用户: "现在几点？"
工具结果: "2024-01-01 12:00:00"
LLM: 现在是 2024年1月1日中午12点整
```

- [ ] `core.py`：Agent 能正确调用工具并返回结果

```python
# 和风天气 API 示例
import requests

def get_weather_hefeng(city: str) -> str:
    """
    查询指定城市的天气（使用和风天气 API）。
    :param city: 城市名称，如"北京"。
    :return: 天气信息。
    """
    API_KEY = "your_hefeng_api_key"  # 替换为你的 API Key
    
    # 1. 先查询城市ID
    city_url = f"https://geoapi.qweather.com/v2/city/lookup?location={city}&key={API_KEY}"
    city_response = requests.get(city_url)
    city_data = city_response.json()
    
    if city_data["code"] != "200" or not city_data["location"]:
        return f"未找到城市：{city}"
    
    city_id = city_data["location"][0]["id"]
    city_name = city_data["location"][0]["name"]
    
    # 2. 查询天气
    weather_url = f"https://devapi.qweather.com/v7/weather/now?location={city_id}&key={API_KEY}"
    weather_response = requests.get(weather_url)
    weather_data = weather_response.json()
    
    if weather_data["code"] != "200":
        return f"获取天气失败：{weather_data.get('message', '未知错误')}"
    
    now = weather_data["now"]
    result = f"{city_name}当前天气：\n"
    result += f"温度：{now['temp']}°C\n"
    result += f"体感温度：{now['feelsLike']}°C\n"
    result += f"天气：{now['text']}\n"
    result += f"湿度：{now['humidity']}%\n"
    result += f"风向：{now['windDir']} {now['windScale']}级"
    
    return result
```

## 阶段四：记忆机制 V2（SQLite + ChromaDB）（3-4天）

**目标**：为 Agent 增加可持久化、可检索的长期记忆，理解“结构化存储 + 向量检索”的分层设计

### 4.1 先理解要解决什么问题

当前版本的 Agent 已经支持多轮对话，但它的“记忆”本质上只有 `self.messages`：

- 程序一旦重启，历史上下文就丢失
- 对话轮数太多时，`messages` 会越来越长
- Agent 无法跨会话记住用户的长期偏好和历史事实

因此，阶段四要解决的是：

1. **短期记忆**：继续保留 `messages`
2. **长期记忆**：把稳定信息持久化到本地存储
3. **语义召回**：当用户提出新问题时，能找回“语义相关”的历史记忆

### 4.2 V2 方案总览

在这一阶段中，我们采用如下分工：

- `SQLite`：保存结构化元数据，例如 `user_id`、`memory_type`、`content`、`importance`
- `ChromaDB`：保存文本向量并负责相似度检索
- `memory.py`：负责把写入、召回、重排序、格式化串起来
- `core.py`：负责把记忆机制接入 Agent 主流程

### Step 4.1: 编写结构化存储层（`src/store.py`）- 第1天

**任务**：用 SQLite 保存长期记忆的结构化元数据

建议先保存这些字段：

- `id`：主键
- `user_id`：用户标识
- `memory_type`：记忆类型，例如 `fact`、`preference`、`task`
- `content`：记忆文本
- `importance`：重要性分数
- `chroma_id`：对应的 ChromaDB 文档 ID
- `created_at`：创建时间
- `last_accessed_at`：最近访问时间

**推荐代码骨架**：

```python
import sqlite3
from datetime import datetime


class MemoryStore:
    def __init__(self, db_path: str = "data/memory.db"):
        self.db_path = db_path
        self._init_db()

    def _init_db(self):
        conn = sqlite3.connect(self.db_path)
        conn.execute("""
        CREATE TABLE IF NOT EXISTS memories (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            user_id TEXT NOT NULL,
            memory_type TEXT NOT NULL,
            content TEXT NOT NULL,
            importance REAL DEFAULT 0.5,
            chroma_id TEXT,
            created_at TEXT NOT NULL,
            last_accessed_at TEXT
        )
        """)
        conn.commit()
        conn.close()

    def add_memory(self, user_id, memory_type, content, importance, chroma_id):
        conn = sqlite3.connect(self.db_path)
        conn.execute(
            """
            INSERT INTO memories
            (user_id, memory_type, content, importance, chroma_id, created_at)
            VALUES (?, ?, ?, ?, ?, ?)
            """,
            (user_id, memory_type, content, importance, chroma_id, datetime.now().isoformat())
        )
        conn.commit()
        conn.close()

    def get_memories_by_chroma_ids(self, chroma_ids):
        if not chroma_ids:
            return []
        conn = sqlite3.connect(self.db_path)
        placeholders = ",".join(["?"] * len(chroma_ids))
        rows = conn.execute(
            f"SELECT id, user_id, memory_type, content, importance, chroma_id FROM memories WHERE chroma_id IN ({placeholders})",
            chroma_ids
        ).fetchall()
        conn.close()
        return rows
```

**这一阶段重点理解**：

1. SQLite 不负责向量相似度计算
2. SQLite 负责的是“结构化记录管理”
3. `chroma_id` 是连接两套存储的桥梁

**验证点**：

- [ ] 能成功插入一条记忆

```python
import chromadb


class VectorStore:
    def __init__(self, persist_directory: str = "data/chroma"):
        self.client = chromadb.PersistentClient(path=persist_directory)
        self.collection = self.client.get_or_create_collection(name="tinyagent_memory")

    def add_text(self, doc_id: str, text: str, metadata: dict | None = None):
        self.collection.add(
            ids=[doc_id],
            documents=[text],
            metadatas=[metadata or {}],
        )

    def search(self, query_text: str, top_k: int = 5):
        result = self.collection.query(
            query_texts=[query_text],
            n_results=top_k,
        )
        return result["ids"][0]

    def delete(self, doc_id: str):
        self.collection.delete(ids=[doc_id])
```

### Step 4.3: 编写记忆管理器（`src/memory.py`）- 第3天

**任务**：把 SQLite 和 ChromaDB 串起来，形成完整的记忆读写链路

`memory.py` 需要至少提供三个核心方法：

1. `write_back()`：从本轮对话中提炼新记忆
2. `recall()`：基于当前问题召回相关记忆
3. `format_for_prompt()`：把召回结果转成适合注入 Prompt 的文本

**推荐代码骨架**：

```python
from uuid import uuid4


class MemoryManager:
    def __init__(self, client, store, vector_store):
        self.client = client
        self.store = store
        self.vector_store = vector_store

    def recall(self, user_id: str, query: str, top_k: int = 5):
        chroma_ids = self.vector_store.search(query_text=query, top_k=top_k)
        rows = self.store.get_memories_by_chroma_ids(chroma_ids)
        rows = [row for row in rows if row[1] == user_id]
        rows.sort(key=lambda x: x[4], reverse=True)
        return rows

    def write_back(self, user_id: str, user_message: str, assistant_message: str):
        if len(user_message.strip()) < 6:
            return

        content = f"用户说：{user_message}；助手回答：{assistant_message}"
        memory_type = "task"
        importance = 0.6
        chroma_id = str(uuid4())

        self.vector_store.add_text(
            doc_id=chroma_id,
            text=content,
            metadata={"user_id": user_id, "memory_type": memory_type},
        )
        self.store.add_memory(
            user_id=user_id,
            memory_type=memory_type,
            content=content,
            importance=importance,
            chroma_id=chroma_id,
        )

    def format_for_prompt(self, memories):
        lines = []
        for _, _, memory_type, content, importance, _ in memories:
            lines.append(f"[{memory_type}][{importance}] {content}")
        return "\n".join(lines)
```

**第一版不要追求太复杂**：

- 先用规则写入记忆
- 先用 ChromaDB 原生检索
- 先只实现 `fact / preference / task` 三种基础类型

等跑通后，再升级为：

- 用 LLM 提炼结构化记忆
- 增加去重
- 增加时间衰减和重排序

**验证点**：
- [ ] 一轮对话结束后，能自动写入长期记忆
- [ ] 新问题到来时，能召回相关历史信息
- [ ] 返回给 LLM 的记忆文本格式清晰可读

### Step 4.4: 修改 Agent 主流程（`src/core.py`）- 第3-4天

## 常见问题

### Q1: LLM 不调用工具怎么办？

**可能原因**：
1. 工具描述不够清晰
2. LLM 认为不需要工具
3. 模型不支持 Function Calling

**解决方案**：
在系统提示中强调使用工具：
```python
SYSTEM_PROMPT = """
你是一个AI助手。当用户问时间、计算、搜索等问题时，
**必须**调用相应的工具函数，不要直接猜测。
"""
```

### Q2: 工具调用参数错误？

**解决方案**：在工具函数中添加参数校验
```python
def add(a: float, b: float) -> str:
    try:
        result = float(a) + float(b)
        return str(result)
    except (ValueError, TypeError) as e:
        return f"参数错误: {e}"
```

### Q3: 对话历史太长？

**解决方案**：实现上下文截断
```python
def manage_context(self):
    """管理对话历史长度"""
    # 保留系统消息 + 最近 10 轮对话
    if len(self.messages) > 20:
        self.messages = [self.messages[0]] + self.messages[-19:]
```

### Q4: 为什么长期记忆要拆成 SQLite 和 ChromaDB 两层？

**解决方案**：让两种存储各司其职

- `SQLite` 适合保存结构化字段，例如用户、类型、时间、重要性
- `ChromaDB` 适合保存向量并做语义相似度检索
- 两层拆开后，更符合真实项目中的工程分层，也更方便调试

### Q5: 为什么不能把所有聊天原文都写进长期记忆？

**解决方案**：只保留高价值信息

- 聊天原文噪声很多，会污染召回结果
- 长期记忆应该保存“稳定、可复用、跨会话有价值”的内容
- 最好做类型分类、重要性评分和定期清理
